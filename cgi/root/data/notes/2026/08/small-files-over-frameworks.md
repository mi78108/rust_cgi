我之前给 /chatroom 写过一个 600 行的 SPA "框架", 现在看回去只想删掉。问题是: 我自己写的"框架", 我自己读起来都卡。

新规则, 强制 50 行:

- 一个文件不超过 50 行 (不算注释/空行)
- 每个文件做一件事, 命名就是动词 (fetch_messages.js / connect_ws.js)
- 模块之间通过全局 `document.chatroom` 对象通信, 不引入 import/export, 不上 bundler
- 任何超过 50 行的文件, 拆, 不允许以 "逻辑复杂" 为由不拆

trade-off: 多文件, 多 script 标签。收益: 哪天要 debug, 我能在 5 秒内定位到对的那 50 行。

今天给 /notes 写前端用的也是这套思路 —— 一个 50 行 fetch + 一个 50 行 markdown 渲染, 一个 50 行事件总线。三个文件, 刚好。

唯一不适用的场景: 团队协作。这种结构适合单兵 / 双人, 三人以上就开始冲突。
